# Gym-Beam: категории, собственный вес и любые три упражнения

Дата пользователя: 2026-10-16, Europe/Moscow. Папка `C:\gymbeam`, PowerShell, Node24/pnpm. Предыдущая завершённая версия описана в `CHECKPOINT_2026-10-16_CALIBRATION_UPDATES.md`; APK1.1.0/code6 уже содержит Expo Update.

## Цель

Выбирать категорию при любом создании упражнения, учитывать вес тела в тоннаже (также в истории), повышать игровой уровень по любым трём различным упражнениям каталога, а не только жиму/приседу/тяге. Протестировать, сохранить в master и доставить совместимой OTA без нового APK.

## Реализация И Решения

- `components/EquipmentPicker.tsx`: общий раскрываемый выбор Штанга/Гантели/Собственный вес/Тренажёры/Другое. Категория нового упражнения не предвыбрана; сохранение требует выбора.
- `ExercisePicker.tsx` и активная тренировка: быстрый onCreate передаёт equipment третьим параметром. В каталожном `ExerciseEditor.tsx` используется тот же компонент. Старый API допускает отсутствующее поле как other для совместимости; явно неверная категория отклоняется. Пользовательский UI всегда требует выбор.
- `workoutMeasurement.ts`, `offlineApi.ts`: для повторных bodyweight упражнений тоннаж `(bodyWeightKg + extraWeightKg) * reps`. `weightKg` остаётся ДОПОЛНИТЕЛЬНЫМ весом: данные подходов/степперы/ИИ не подменяются полной массой. Штанга/гантели/тренажёры без прибавления веса тела. Планка остаётся в секундах, тоннаж0.
- Новые bodyweight подходы сохраняют optional `SetRow.bodyWeightKg` из профиля на момент добавления. Последующее изменение профиля не переписывает их объём. Если масса тогда не была задана, исторический снимок не выдумывается.
- Для старых подходов без снимка берётся текущая масса из профиля, результат помечается `bodyWeightEstimated=true` и подписью «расчётный». Если масса вообще не задана, учитывается только известный добавленный вес; подпись «Вес тела не указан; тоннаж неполный». В активной тренировке есть действие «Указать вес тела» или показ тела+общей нагрузки. НЕ использовать нормативный fallback75кг как будто это измеренная масса для тоннажа.
- Пересчёт централизован в enrichSet, поэтому совпадают активная тренировка, история, отчёт, статистика, графики, сравнения и breakdown. Старые сырые записи не переписываются. SetCard и история показывают происхождение массы через formatSetContext.
- `progressBackup.ts` проверяет optional снимок: число20..500, только у bodyweight подходов, не timed. Формат остаётся v8: optional поле, прежние copies1..8 совместимы, массивы normalizeState сохраняют поля, старый v8 parser имеет passthrough. Проверки целостности сохранены.
- `levelProgress.ts`: единый targetForExerciseLevel в кг/повторах/секундах. Ступени III/II/I/КМС/МС/МСМК берутся из существующих exerciseStandard. Промежуточные игровые шаги интерполируются между соседними ступенями, не процентами МСМК. Для3официальных lifts все thresholds точно совпадают с прежними WRPF-таблицами. Остальные шкалы остаются условными, НЕ официальными званиями.
- Кандидаты: все упражнения, включая custom и isMain=false; реальные лучшие одиночные подходы из ЗАВЕРШЁННЫХ тренировок. Повторы/секунды не суммируются для ранга, тоннаж и незавершённые подходы уровня не дают. Общий уровень равен третьему по величине достигнутому уровню разных exerciseId. Повторяющиеся подходы не заменяют разные упражнения.
- Сохраняется прежняя гарантия удаления: soft-deleted упражнения с записанной историей сохраняют достижения и видны как «архив», удалённые без истории не считаются. Удаление самой тренировки/подходов пересчитывает уровень. Это не потеря реальных записей при удалении из каталога.
- `LevelsScreen`: три лучших кандидата + раскрываемые «Все упражнения». Условные нормативы подписаны как ориентиры, единицы корректны; формулировка «Любые три упражнения», игровая ступень не называется присвоенным спортивным разрядом. Расширение ответа LevelsResponse локально типизировано ExerciseLevelsResponse, старые weight-only поля сохраняются для совместимости.
- Изменения относятся к автономному мобильному приложению. Legacy PostgreSQL/web сервер не переводился на новый алгоритм: его старые DB-контракты не участвуют в APK.
